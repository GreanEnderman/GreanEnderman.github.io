# 个人博客产品方案

## 1. 项目概述

这个博客的定位是一个长期维护的个人数字刊物。
它首先服务于你自己的记录、写作与积累，同时也为未来的求职展示、
项目沉淀和合作引流预留空间。

它不应该像一个常见的个人主页，也不应该像套模板生成的作品集网站。
更合适的目标，是把它做成一个持续更新、阅读体验稳定、风格克制的独立内容站点。

## 2. 核心目标

- 持续记录生活、学习和技术思考
- 发布技术文章、项目复盘和工具分享
- 沉淀可复用的个人内容资产，为未来求职加分
- 给潜在合作方留下一个可信、低压力的了解入口

## 3. 设计原则

- 内容优先：先展示写作和项目，而不是先展示身份
- 阅读优先：文章详情页比首页装饰更重要
- 结构克制：分类少而稳，便于长期维护
- 气质统一：技术文和随笔模板可以不同，但整体调性要一致
- 维护轻量：发布流程尽量简单，不让写作变成负担

## 4. 目标受众

主要受众：

- 你自己

次级受众：

- 朋友
- 未来面试官
- 潜在合作方或客户

这意味着博客首先要满足自用，但同时也要足够清晰、专业、好浏览，
让外部访客能够快速理解你在持续产出什么。

## 5. 站点定位

推荐定位描述：

> 一个以技术写作、个人随笔和项目沉淀为核心的个人数字刊物，
> 以阅读体验为优先，强调长期内容积累。

关键词：

- 克制
- 理性
- 偏极客
- 报刊感
- 匿名
- 低饱和

## 6. 信息架构

主导航建议：

- 首页
- 文章
- 项目
- 关于

次级入口建议：

- 搜索
- 归档
- 友链
- 留言

内容主结构：

- 文章
  - 技术
  - 随笔
- 项目

组织方式建议：

- 使用少量主分类
- 使用标签做细分
- 使用归档承担长期浏览入口

这样既能保持结构清晰，也能避免内容增长后分类体系变得臃肿。

## 7. 内容策略

计划中的主要内容类型：

- 前端与后端技术文章
- 读书笔记
- 生活随笔
- 项目复盘
- 工具分享

摄影内容目前优先级较低，更适合作为辅助表达，而不是单独的内容支柱。

建议的更新节奏：

- 技术文章：低频但更有深度
- 随笔和读书记录：中频、轻量
- 项目复盘：按阶段节点更新

这样的节奏更可持续，也更适合长期维护。

## 8. 首页策略

首页方向：

- 内容型首页
- 不做个人名片式首页

推荐首页结构：

1. 一句简短的站点宣言
2. 精选内容区
3. 分栏目内容区
4. 最新更新时间流
5. 页脚快捷入口

建议模块拆分：

- 站点宣言
- 1 篇精选文章
- 1 个精选项目
- 最近技术文章
- 最近随笔
- 最近更新流
- 归档 / 友链 / 留言入口

这样的结构能形成明确的杂志感，同时又不牺牲浏览效率。

## 9. 文章体验

博客应支持两套文章模板。

### 技术文章模板

适用场景：

- 教程
- 深入分析
- 项目复盘
- 工具分享

特征建议：

- 清晰的目录
- 阅读进度
- 明确的标题层级
- 代码高亮
- 提示块或注释块

### 随笔模板

适用场景：

- 读书笔记
- 生活写作
- 个人反思

特征建议：

- 更柔和的留白节奏
- 更突出的导语与引用
- 更少的界面干扰
- 更强调文字本身的阅读感

这两套模板应该属于同一个站点气质，而不是像两个完全不同的网站。

## 10. 项目模块

项目应作为独立板块存在，但与文章保持联动。

每个项目页建议包含：

- 项目简介
- 项目定位或职责
- 技术栈
- 核心亮点
- 截图或演示
- 仓库地址和在线地址
- 当前状态
- 关联复盘文章

和文章的关系建议：

- 项目页挂关联复盘文章
- 文章页反向链接项目页

这样项目展示就不会是孤立的陈列，而是和内容沉淀互相支撑。

## 11. 关于页

关于页应当完整，但不过度强调个人品牌。

建议包含：

- 简短经历
- 技术栈与关注方向
- 代表项目
- 兴趣爱好
- 合作方式
- 联系方式

因为整体基调偏匿名，这一页更适合突出能力、兴趣和工作方式，
而不是做成强曝光的自我营销页面。

## 12. 视觉方向

期望的视觉气质：

- 报刊感
- 克制
- 低饱和
- 理性
- 安静

建议的视觉语言：

- 基础配色：米白、炭黑、浅灰
- 点缀配色：蓝灰或低饱和墨绿
- 字体方向：正文偏阅读型字体，元信息和代码相关区域可配等宽字体
- 布局方向：强调网格、留白和细分隔线
- 组件方式：少阴影，多边框和版式层次
- 图片策略：少而精，避免装饰性滥用
- 动效策略：只做轻微淡入和小幅过渡

避免模板味的关键，不是做复杂，而是有明确的编辑逻辑、排版节奏和稳定的视觉规范。

## 13. 功能优先级

### 第一阶段

- Markdown 或 MDX 写作
- 技术 / 随笔双栏目
- 标签
- 归档
- 全文搜索
- 代码高亮
- 文章目录
- 阅读进度
- 深色模式
- 项目页
- 访问统计

### 第二阶段

- 留言板或评论
- 友链页
- 简历页
- 知识库入口
- 多语言结构预留

### 第三阶段

- 多语言内容
- 系列文章导航
- 专题页
- 阅读清单
- 更完整的摄影展示

## 14. 评论与互动

你需要的互动方式更偏轻量、朋友交流感，而不是社区讨论感。

建议策略：

- 初期更像留言板
- 评论区视觉上保持安静
- 不让互动区抢走文章主体的注意力

实现方向建议：

- 如果访问者主要是技术圈朋友，优先 `giscus`
- 如果后续希望更轻量、更像普通留言，可再考虑 `Waline`

## 15. 技术选型建议

推荐技术组合：

- 框架：Astro
- 内容层：Astro Content Collections
- 写作方式：Markdown + MDX
- 搜索：Pagefind
- 统计：Umami 或 GoatCounter
- 评论：初期可选 giscus
- 部署：GitHub Pages

### 为什么推荐 Astro

Astro 很适合这个博客，因为它：

- 很适合内容型静态站点
- 与 GitHub Pages 配合顺畅
- 对 Markdown / MDX 支持成熟
- 页面性能好，适合阅读优先的站点
- 自定义空间足够大，适合做出自己的报刊感风格
- 后续扩展项目页、归档页、知识库都比较自然

### 为什么不优先选其他方案

- Hexo：简单，但长期自定义空间和扩展性一般
- VitePress：更偏文档站，不够适合你的内容气质
- Next.js：能力强，但对当前需求来说偏重

## 16. Astro 落地方向

建议目录结构：

```text
src/
  components/
    site/
    post/
    project/
    common/
  layouts/
    BaseLayout.astro
    PostLayoutTech.astro
    PostLayoutEssay.astro
    ProjectLayout.astro
  content/
    posts/
      tech/
      essays/
    projects/
  pages/
    index.astro
    posts/
      index.astro
      [slug].astro
    projects/
      index.astro
      [slug].astro
    about.astro
    archive.astro
    search.astro
    links.astro
    guestbook.astro
  styles/
    tokens.css
    global.css
    prose.css
```

推荐文章字段：

- `title`
- `description`
- `date`
- `updated`
- `category`
- `tags`
- `draft`
- `featured`
- `series`
- `cover`
- `toc`
- `lang`
- `project`
- `template`

推荐项目字段：

- `title`
- `description`
- `date`
- `status`
- `stack`
- `featured`
- `repo`
- `demo`
- `cover`
- `relatedPosts`

其中 `template` 字段很重要，它可以让文章根据写作类型选择模板，
而不是只根据分类来决定页面样式。

## 17. 开发顺序建议

推荐开发顺序：

1. 先搭内容模型和基础路由
2. 完成首页和两套文章模板
3. 完成项目页和关于页
4. 加入归档、标签、搜索
5. 最后补评论、统计和细节打磨

这样可以保证你先拥有一个可写、可读、可维护的博客骨架。

## 18. 最终产品愿景

最终这个博客应该呈现为：

- 一个匿名作者持续更新的个人刊物
- 一个以阅读为核心的技术与生活内容档案
- 一个安静但可信的职业展示面
- 一个未来可以自然扩展成简历页、作品集和知识库的长期站点

简单说，首页先回答“这里在持续写什么”，整个站点再慢慢回答
“持续写这些内容的人，是什么样的人”。
